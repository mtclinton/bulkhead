# bulkhead — Production Readiness

bulkhead is a single-purpose Linux security appliance that makes AI-agent isolation an OS primitive (Yocto image + Go TCB services + eBPF/BPF-LSM; 42 ADRs in `docs/decisions/`). This document is an honest gate list, not a status report — every item cites an ADR and a `make verify-*` target or source file, and every "Done when" is a concrete, testable criterion.

**What is done.** The security *substrate* is mature and qemu-verified end to end. The boot/update spine (A/B verity bundles + rollback, ADR-0001/0003), the BPF-LSM action floor (E0–E3, ADR-0004) booting harden-by-default armed (ADR-0018), the egress/delegation/approval mediation with three signed, hash-chained, domain-tagged, cross-boot, bounded-retention audit chains (ADR-0006/0007/0013/0017/0040), structural egress confinement through a signing proxy (ADR-0034), the gVisor/runsc default isolation tier (ADR-0031), io_uring compiled out (ADR-0033, amended 2026-06-18), and the remote-attestation + no-rewind machinery (ADR-0019–0026) are all in the image and exercised by `verify-*` targets that boot qemu and assert behavior.

**What is not.** The qemu harness runs `-cpu IvyBridge` with **no nested KVM** and an unreliable vTPM, so the entire hardware-rooted tier is build-verified-only: real-TPM2 PCR-7 sealing (ADR-0008/0028), Secure Boot key enrollment, the Firecracker hostile tier's jailer/CID/multi-instance runtime (ADR-0042), and runsc `--platform=kvm`. No appliance has ever booted on physical hardware. The agent today is a probe/demo driven by a `mockchat` stub — the product's reason for being (safely running a *real* tool-using agent against a *real* model) is unproven. The operational/day-2 layer (off-box audit-chain monitor, metrics, IR runbook, backup/restore, fleet rollout, HSM-backed signing, provisioning at scale) is largely **absent**. And every security claim rests on self-review: there has been **no external red-team or third-party audit**.

**Critical path to production.** Burn down the Pilot blockers — bare-metal commissioning, the real-TPM2 sealed boot, the real agent-workload-on-real-model loop, the off-box chain monitor, and the minimum day-2 ops (metrics, IR runbook, key/secret management) — to reach a controlled single-operator pilot on real hardware. GA additionally requires hardware-rooted attestation against genuine EK certs, fleet/canary rollout, HSM signing custody, soak/power-loss/load harnesses, backup/restore, and an independent external assessment.

## Status legend

`shipped-live-proven` = in the image AND proven by a qemu-booting `verify-*` · `build-verified-bare-metal-pending` = in the image + build/config-verified, runtime NOT proven here (no nested KVM / no real TPM / no real HW) · `partial` = some increments shipped, others deferred · `proposed-unbuilt` = ADR in Proposed status or design with no implementation · `absent` = a real production concern with NO ADR and NO implementation.

## 1. Pilot blockers

Must-have for a controlled, single-operator deployment on real hardware.

### boot-update-attest

- [ ] **Bare-metal TPM2 sealed-boot, end-to-end (audit seed + MITM CA under real PCR-7)** — `build-verified-bare-metal-pending` — evidence: ADR-0008/ADR-0028 (`BULKHEAD_SEAL_KEY=tpm2`, five `LoadCredentialEncrypted` drop-ins; mechanism spike-proven under swtpm) + ADR-0034 sub-B (re-signing CA seal); shipped default is `plain`. The qemu vTPM EPROTOs PID1 `LoadCredentialEncrypted` (systemd #21747) and OVMF leaves PCRs 0–9 zero, so the live tpm2 boot has never run; no script even greps `SEAL_KEY=tpm2`. Done when: on hardware with a real TPM2 + enrolled Secure Boot keys, a `BULKHEAD_SEAL_KEY=tpm2` image cold-boots with all four seed consumers (collector/broker/router/verify-audit) unsealing the PCR-7-bound seed at unit start, re-unsealing identically across reboot, and a forced PCR-7 perturbation fail-closes the boot.
- [ ] **Real-hardware A/B install + power-loss-safe rollback on physical storage** — `shipped-live-proven` (qemu) / hardware-pending — evidence: ADR-0001/ADR-0003 (verity bundles, A/B+rescue+data wic), ADR-0039 no-downgrade hook; `make verify-rauc` (3-boot A→B→mark-bad→rollback) + `make verify-rauc-hook`. Proven only under OVMF/swtpm with a virtio-attached bundle; real eMMC/SSD slot writes, grubenv durability across power-cut, and tailnet-delivered signed bundles are unexercised. Done when: on hardware, `rauc install` of a CA-signed verity bundle over the tailnet flips the inactive slot, survives a power-cut mid-write (atomic, no half-slot boot), auto-rolls-back via grubenv try-count on a deliberately-bad slot, and /data + sealed creds persist across the switch.

### egress-audit-mediation

- [ ] **Default-deny network floor authoritative on a real NIC (not slirp)** — `partial` — evidence: ADR-0001 #11 (nftables drop-policy + dnsmasq→nftset) + ADR-0034 inc1 (structural signing proxy is the future authoritative chokepoint); `make verify-egress`, `verify-egress-proxy`, `verify-egress-reboot`. Proven only against qemu slirp loopback/mock upstreams; the name→IP allowlist is advisory and direct-IP bypass on a real route is untested. Done when: on a real NIC an unlisted host (by name and by IP literal) is denied at the floor, an allowlisted real HTTPS host is reachable ONLY via the proxy's signed-decision path (direct-IP bypass blocked), and DNS for non-allowlisted names does not leak.
- [x] **Continuous off-box monitor of the signed audit-chain HEADs (the witness)** — `shipped-live-proven` — evidence: `bulkhead-chain-monitor` (`src/chain-monitor`, `deploy/chain-monitor.md`) polls each device's fresh-nonce quote, verifies it via the shipped `attest verify` (AK-pinned, expected-D), pins the three quote-bound HEADs (ADR-0025) and runs `verify-audit --since=<prior-pinned> --expect-tip=<quoted>` (ADR-0026) per chain, alerting on a missed attestation / quote-verify fail / chain rewind-or-fail and keeping the last-good anchor. Proven by `make verify-chain-monitor` (the pin/advance/rewind/missed state machine, 8 unit tests) AND `make verify-chain-monitor-live` (boots the wic, the monitor binary pins the control HEAD off-box, then a tail-truncation on the box fires `chain-rewind-or-fail` — 8/8). The remaining work is the DEPLOYMENT (next item), not the mechanism. Closes "the off-box anchor is not yet wired" (`docs/threat-model.md`).

### agent-isolation

- [ ] **Per-agent BPF-LSM action floor (E0–E3) + harden-by-default arm on the production kernel** — `shipped-live-proven` — evidence: ADR-0004 (E0 bpf/E1 ptrace/E2 egress-class/E3 setuid+capset; deny-only ratchet, fail-open, TCB-exempt) + ADR-0018 (cold-boot armed E0+E2); `make verify-e0` + `make verify-hbd` + `verify-egress-class`. Coupled to fixed `vmlinux.h` offsets on kernel 6.6.127; a kernel bump requires re-deriving offsets + re-proving deny-safety, and no offset-drift guard exists. Done when: an automated regression on the production kernel re-verifies the bpf2go object loads, all E0–E3 arm (deny + TCB-exempt allow) on bare metal, and a `vmlinux.h` offset-drift check fails the build if offsets change without re-derivation.
- [ ] **Agent jail floor denies io_uring by name in every template + holds against a hostile (not cooperative) payload** — `shipped-live-proven` — evidence: ADR-0005 (`bulkhead-agent@.service` floor: DynamicUser, empty caps, NoNewPrivileges, `@system-service`+EPERM, RestrictNamespaces/AddressFamilies) + ADR-0033 (io_uring subtracted by name since `@system-service` permits `@aio`); `verify-egress-proxy`/`verify-egress-reboot` assert in-jail EPERM. ADR-0031 reclassifies this shared-kernel jail as the *weakest* boundary. The **build-time grep is now DONE** — `scripts/floor-lint.sh` (`make verify-floor-lint`, in CI) dynamically discovers every `@system-service`-based agent jail and fails the build if it does not deny `io_uring_setup/enter/register` (drop-in/reset/additive aware) — guarding this + the kernel-compile-out + the mux/mediation/nftables/AF_UNIX/runsc/Requires-selftest/PrivateNetwork/IPAddressDeny floors against silent regression. Done when: (remaining) a hostile arm shows the floor + E2 manifest hold while the payload actively probes for escape.

### real-workload

- [ ] **Real tool-using agent loop against a real model through all tiers** — `partial` — evidence: ADR-0014 (real `runLoop`/`planexec` in `src/agent`, CGO off) runs CONFINED via `make verify-confined-agent` + `make verify-quarantine`, but every end-to-end target points the router at a `mockchat` stub (`src/agent/mockchat.go`, unit never enabled); the only real-inference test (`verify-service`) runs a tiny GGUF on the Buildroot image, not the production wic. The agent is a probe/demo, not a tool-user. Done when: on bare metal with the GPU + a real model behind the router, the real agent loop runs a non-trivial multi-step task to a parseable FINAL with every egress kernel-confined or human-gated and signed, ADR-0036's injection property holds against the real model, and no `mockchat` is in the path.

### operational-day2

- [ ] **Bare-metal commissioning checklist executed on reference hardware** — `build-verified-bare-metal-pending` — evidence: the qemu harness (`-cpu IvyBridge`, unreliable vTPM) leaves tpm2 sealing (ADR-0008/0028), the Firecracker jailer (ADR-0042 slices 5–6, `verify-firecracker-image` is a rootfs-landing lint), and KVM-platform runsc config-verified only; `yocto/scripts/run-qemu-tpm.sh` is the single launcher and no target boots real hardware. Done when: a commissioning checklist runs once on target HW: tpm2 unseal of the audit seed AND the MITM CA under real PCR-7 (forced PCR change fail-closes), the Firecracker jailer + 2-instance isolation arm green on `/dev/kvm`, runsc `--platform=kvm` green, real-NIC egress mediated+signed, and a tested PCR-7 seed-escrow restore runbook.
- [ ] **Bare-metal boot harness: flash the wic to a real target and run the floor/egress/attest assertions** — `absent` — evidence: every Yocto `verify-*` funnels through `run-qemu-tpm.sh` (`runqemu ... slirp`) with the vCPU pinned to IvyBridge (`qemuboot-x86.inc` `QB_CPU/QB_CPU_KVM ?= -cpu IvyBridge`, no nested VMX); there is NO target that provisions or boots physical hardware. slirp masks real nftables/route/DNS-leak behavior. Done when: a documented bring-up + host-side harness flashes the wic to a real target (or PXE/USB-boots it), waits for the collector to arm, and runs the existing floor/egress/attest assertions over serial — passing on at least one reference SKU.
- [ ] **Off-box audit-chain monitor + alerting deployed** — `partial` — the monitor binary + its alert hook (`alert_cmd`, `-once` for cron) ship and the truncate drill is live-proven (`verify-chain-monitor-live`); what remains is the operational DEPLOYMENT: run it always-on over the management plane against the real fleet (the example transport is ssh-over-tailnet, `deploy/chain-monitor.example.json`), wire its alerts to real routing, and pin the TOFU AK + initial HEADs at provisioning. Done when: the monitor runs as a managed service polling the real devices with alerts wired to an on-call path, exercised end-to-end by a kill-append + truncate drill on a real device.
- [ ] **Operational metrics / health / observability for live services** — `absent` — evidence: only the router has `GET /health` (`src/router/server.go`); no `/metrics`/expvar/pprof on router/proxy/collector, no telemetry recipe in `meta-bulkhead`. A failing-but-not-crashed TCB service is invisible. Done when: each service exposes a scrapeable metrics surface (egress decide/deny counts, proxy latency, jail-spawn outcomes, chain-append errors, broker queue depth) reachable only over the management plane, with a documented dashboard + alert rules and a test asserting key counters move under load. (New ADR required — a TCB metrics surface is itself attack surface.)
- [~] **Incident-response & tamper-evidence runbook** — `partial` (was absent) — evidence: `docs/INCIDENT-RESPONSE.md` now enumerates 13 detection signals (the off-box monitor's 3 alert kinds + verify-audit/selftest/attest gates + enforce-degrade + PCR-7/seed + nftables drop-log + crash-loops) and the triage→preserve→contain→eradicate→recover playbooks A–E + RAUC recovery, each grounded in a real command/unit/ADR with its limits and an honest 12-item gaps section. Remaining: a tabletop or scripted DRILL exercising at least the tamper-detected + missed-attestation paths end-to-end (the `verify-chain-monitor-live` truncate→alert arm already exercises the chain-tamper detection; a containment drill — NARROW/stop/rollback on a live box — is bare-metal-pending).
- [ ] **Key & secret management for a pilot (per-device seal + escrow/restore)** — `partial` — evidence: per-device sealing is designed (ADR-0008 seed→PCR-7, ADR-0028 bare-metal tpm2, ADR-0020 EK-rooted AK; `deploy/anthropic-credential.md`, `deploy/tailscale-join.md`) but every flow is single-device + manual SSH; ADR-0039's PCR-7 seed-escrow runbook is a deferred seam (no script, no restore path — a firmware/SB/TPM-RMA change perturbs PCR 7 and bricks the box). Done when: a scripted enrollment seals all per-device secrets at provisioning, an escrow path restores the audit seed after an authenticated PCR-7 perturbation, and a tested key-rotation procedure preserves cross-boot chain continuity.
- [ ] **Human approval gate reachable by a remote operator over the tailnet** — `shipped-live-proven` (local) / transport-pending — evidence: ADR-0007/ADR-0009 (`/run/bulkhead/approve.sock` 0600, `SO_PEERCRED uid==0`, exactly-once resolve, separate broker decision chain; `verify-agent-orch` pending→allow/deny/timeout/agent-rejected). The production operator transport (tailnet SSH-as-uid-0 / `tailscale whois`) is a documented seam, NOT built; pending state is in-memory (fail-closed drop on restart). Done when: a remote operator over the ACL'd tailnet approves/denies a real agent escalation end-to-end on bare metal, the decision is signed into the broker chain (`verify-audit` green), and pending requests survive (or fail-closed-drop, asserted) across a broker restart.

### boot-update-attest

- [ ] **Measured-boot PCR population + UEFI Secure Boot key enrollment** — `build-verified-bare-metal-pending` — evidence: ADR-0008 staged (`MACHINE_FEATURES += tpm2`, OVMF TPM_ENABLE, GRUB tpm module, systemd-pcrphase); ADR-0008 states swtpm `TPM2_Startup(CLEAR)` zeroes PCRs 0–9. NO enrolled PK/KEK/db and no sbsign'd bootloader/kernel exist anywhere (`grep` over `meta-bulkhead` returns nothing). Done when: on hardware, enroll bulkhead PK/KEK/db, sbsign GRUB+kernel, boot with Secure Boot on, read non-zero firmware PCRs 0–9, and prove perturbing PCR 7 (different SB key) makes the sealed seed fail to unseal.
- [ ] **Non-ephemeral, fail-closed audit signing key hardware-anchored under PID1** — `partial` — evidence: ADR-0008 two modes (`plain` shipped default vs `tpm2` PCR-7 sealed); seal mechanism spike-proven under swtpm; stable-signer-across-reboot proven via `verify-yocto-router`/`verify-egress-reboot`/`verify-attest`. The shipped default is plaintext-on-device because PID1 `LoadCredentialEncrypted` EPROTOs under qemu's vTPM. Done when: on bare metal `BULKHEAD_SEAL_KEY=tpm2` first-boot seals to PCR 7, every reboot the collector+broker come up via `LoadCredentialEncrypted` with a stable signer, reading /data yields only ciphertext, and a non-bulkhead-signed kernel (PCR-7 change) makes the collector refuse to start.
- [ ] **Remote attestation rooted in a genuine manufacturer EK cert over firmware PCRs** — `build-verified-bare-metal-pending` — evidence: ADR-0019 (AK-signed PCR-14 quote) + ADR-0020 (EK-cert credential-activation) + ADR-0025 (three chain HEADs bound into the quote); `make verify-attest` (26+ checks incl. negatives) runs under swtpm with self-signed dev PKI — its header flags it proves the *mechanism*, "not silicon-genuineness," and PCRs 0–9 aren't firmware-populated. Done when: on hardware a fresh-nonce AK-signed quote over firmware-rooted PCRs (PCR 7 reflecting a real SB-measured boot) verifies off-box against an EK-cert chained to a manufacturer CA, with N1/N2/N3 (forged-EK, wrong-AK, forged-request) and a bound-HEAD-tamper still failing closed.
- [ ] **Cryptographic self-check gate against a pre-provisioned EK-rooted pin** — `build-verified-bare-metal-pending` — evidence: ADR-0023 (`bulkhead-attest-selfcheck-gate.service`, fresh-nonce PCR-14 quote vs `expectedDefaultArmedD`, catches never-armed boot + runtime map-flip the map-read gate misses); `verify-attest`. The shipped qemu default is the *structural fallback* where the verifying AK is attacker-suppliable (a tampered collector forges the envelope). Done when: on bare metal the box self-checks against `/data/bulkhead/attest-ak.pin` (EK-rooted, not the fallback) so a software-forged quote is rejected, asserted by a target that boots observe and shows the gate fail-closed despite a faked live map.
- [ ] **RAUC update-path hardening: verity-authenticated *running* rootfs + signer revocation** — `shipped-live-proven` (install-side) — evidence: ADR-0039 (mark-good gated on selftest+verify-audit, downgrade floor, keyring gate); `make verify-rauc` + `verify-rauc-hook`. Deferred seams: the booted rootfs has NO dm-verity (verity authenticates the *bundle* at install, not the running root), no CRL/signer-CN pinning, and the live reject-older arm was dropped (busybox `dd`). Done when: a verity-image rootfs carries a roothash on the kernel cmdline (target asserts the booted root is verity-authenticated), an on-device CRL/pinned-signer-CN path exists, and a live reject-older-bundle arm lands in `verify-rauc`.
- [ ] **RAUC bundle signing infrastructure: HSM/KMS custody + revocation** — `partial` — evidence: ADR-0039 wires the device-side anchor (`BULKHEAD_RAUC_KEYDIR`, `RAUC_KEY_FILE`, production-gate fatals without a CA cert) but the signer is a local PEM; no CI workflow (`go.yml`/`gitleaks.yml`/`authorship.yml`) builds or signs a bundle. Done when: release bundles are signed by a key whose private half never leaves an HSM/KMS, a documented key-custody + rotation ceremony exists, the device pins the signer CN and consumes a CRL, and a test shows a bundle signed by a revoked signer is rejected on-device.
- [ ] **Reproducible, attestable release engineering (bit-identical builds + CVE gate)** — `build-verified-bare-metal-pending` — evidence: ADR-0003 #6/#7 (`INHERIT += create-spdx`, all SRCREVs pinned, `OEEquivHash`); off-repo HSM signing is path-configured but unexercised (dev CA only). No two-host bit-for-bit proof and no SBOM-driven CVE gate in the `verify-*` set. Done when: two independent build hosts produce bit-identical artifacts from the pinned manifest, the RAUC bundle is HSM/KMS-signed off the build host, and a CVE gate over the generated SPDX fails the release on a known-vulnerable pinned component.

### agent-isolation

- [ ] **Firecracker hostile-tier microVM + jailer confinement on real /dev/kvm** — `build-verified-bare-metal-pending` — evidence: ADR-0042 (design accepted; slices 1–4 proven HOST-SIDE 2026-06-17, slices 5–6 in-image build-verified 2026-06-18). ### egress-audit-mediation / operational-day2 (proof backbone)

- [ ] **Operator-initiated in-place egress NARROW with always-on broker + connection teardown** — `shipped-live-proven` — evidence: ADR-0010 (`NARROW` on the uid-0 socket, `narrowMask=cur&^req`, agent-slice path predicate, reverify+serialize); `scripts/qemu-narrow-check.py` (clamp/no-op/refuse arms) + signed `narrow-egress` record + `verify-audit`. Done when: the broker runs always-on, a remote operator clamps a named agent in one command, established connections are torn down (or the limit is documented in the runbook), and the clamp persists across the agent's restart.
- [ ] **Default-deny resource authorization atop the substrate (supersede fail-open BPF-LSM)** — `proposed-unbuilt` — evidence: ADR-0035 Status: Proposed — records the decision (resource auth at the OS is the product; MCP servers = untrusted sandboxed domains) but the default-DENY layer is roadmap; it supersedes the shipped fail-OPEN/observe-default ADR-0004 posture only once the ADR-0031 substrate ships. Current enforcement is the *opposite* posture. Done when: ADR-0035 is Accepted with a target showing an agent under the substrate is default-DENIED a syscall/file/network action absent an explicit grant, and an MCP server runs as its own mediated domain whose output cannot reach the agent's full privilege.
- [ ] **Bare-metal commissioning of attestation against a genuine EK chain across a fleet** — `build-verified-bare-metal-pending` — evidence: `qemu-attest-check.py` proves ADR-0019/0020/0021/0022/0025/0026 against self-signed swtpm dev PKI only (no firmware PCRs under OVMF). Done when: a harness enrolls SB keys, signs the bootchain, captures the manufacturer EK cert, and an off-box verifier validates a quote rooted in that EK with PCR 7 reflecting the real measured boot — plus a forged/other-box EK rejected by the chain.

### operational-day2 / external-validation

- [ ] **Power-loss / multi-boot durability harness for the fail-closed chains + /data** — `partial` — evidence: reboot-aware checks each do ONE clean reboot (`qemu-hbd-check.py`, `qemu-yocto-router-check.py`, `qemu-rauc-check.py` 3-boot, `qemu-audit-rotation-check.py`); there is NO ungraceful power-cut (`kill -9 qemu` mid-write) or torn-write recovery test. The chain is fail-closed by design (a corrupt seed bricks boot), so a torn /data write is a day-2 availability risk. Done when: a soak harness power-cycles the wic dozens of times (incl. hard-kill during a chain append) and asserts every boot comes up green-and-link-continuous OR fail-closes cleanly with operator-recoverable state — never a silent corrupt-but-running box.

Done when: a self-hosted runner (`/dev/kvm` + swtpm + sstate cache) builds the wic and runs `verify-security-review` (+ `verify-attest`/`verify-rauc`/`verify-hbd`) on a schedule/PR, so a runtime-floor regression blocks merge/release.
- [ ] **Independent external validation of the proof backbone** — `absent` — evidence: the only review is the self-authored `docs/security-reviews/2026-06-shipped-isolation-review.md` re-run by `verify-security-review`; CI runs only first-party Go tests. Done when: an independent party red-teams a deployed appliance (jail escape, egress bypass, audit-chain forgery, attestation spoofing), findings are tracked to resolution, and any reproducers extend the regression suite. (Overlaps the GA external pen-test item; merge in execution.)

## 3. Hardening & defense-in-depth

### agent-isolation

- [ ] **Inter-agent delegation: per-deployment max-depth ceiling** — `shipped-live-proven` (attenuation) — evidence: ADR-0006 (`childMask = parentMask & requested`, `SO_PEERPIDFD`-attested peer, widening arithmetically impossible) + ADR-0037 depth cap from kernel-attested instance name; `verify-agent-orch`. Delegation depth/breadth is otherwise bounded only by flood caps. Done when: a bare-metal 3+-level chain shows monotone attenuation at every hop with signed records and a per-deployment max-delegation-depth is enforced and tested.
- [ ] **One-shot E1/E3 grant consumed by a real jailed workload** — `shipped-live-proven` (mechanism) — evidence: ADR-0011 (`grant_once` atomic CAS exactly-once, TTL backstop, E0 ungrantable; load/consume/cross-hook/restart-wipe/TTL all pass) + ADR-0012 TCB-context GC. The headline live op is ptrace; E3 setuid/capset consume is host-CAS+disasm-tested, not a live setpriv arm. Done when: a bare-metal arm consumes a setuid/capset grant from a real jailed workload under a narrowed seccomp profile, proving exactly-once + TTL-expiry + restart-wipe with E0 armed and TCB-context clear.
- [ ] **TCB-context GC fault-injection campaign with audited prunes** — `shipped-live-proven` — evidence: ADR-0012/ADR-0013 F1/F5 (`gcLoop` full-recompute, `reconcileTCB` prunes non-{root,collector,live-broker}); harness covers stranded-grant/crash/recycle/non-agent-immunity. `egress_policy` GC is authoritative only via the steady-state loop; the GC's own prunes aren't audited. Done when: on bare metal under E0-armed a kill-9/recycle/restart campaign shows zero stranded `grant_once` within one GC interval and the prunes appear in a signed audit record.
- [ ] **E0-armable bpf() chokepoint: fold broker RMW onto the control socket** — `shipped-live-proven` — evidence: ADR-0016 (`control.sock` 0660 root:root, `SO_PEERCRED uid==0`+`SO_PEERPIDFD`; `verify-e0` E0-DENY before/after + DELEGATE-UNDER-E0). EXPAND/NARROW/GRANT-ONCE RMW still runs in-broker, so "ONLY the collector ever bpf()s" isn't yet structural. Done when: an adversarial test shows no non-collector process can `bpf()`-write under armed-E0 even via the broker path, OR the broker RMW is folded onto the control socket and the in-TCB reconcile is instant — on bare metal.
- [ ] **Posture self-attest gate: continuous teardown / break-glass** — `shipped-live-proven` (join gate) — evidence: ADR-0021 (`bulkhead-attest-gate.service` reads E0+E2+tcb_clean; `verify-attest` cold-boot OK + stop-enforce fail-closed-fast). Gates only the JOIN, not a live kill-switch; an in-TCB map-flip back to fake-armed defeats it. Done when: a documented break-glass + continuous-teardown `BindsTo` timer is exercised, or the map-read gate is accepted as boot/restart-time-only (load-bearing gate is the ADR-0023 crypto selfcheck).
- [ ] **Model-routing quarantine: replanning + Q-LLM in its own domain** — `shipped-live-proven` (static-plan) — evidence: ADR-0036 inc1+inc2 (P/Q-LLM/`planexec` split, fail-closed `parsePlan` rejects IF/WHILE/GOTO/$var-FETCH; `make verify-quarantine`, `verify-runsc-quarantine`; typed-taint DELEGATE). Static-plan only (CaMeL = 0% on dynamic); the interpreter is now trusted TCB-adjacent code with no separate isolation. Done when: either a replanning-capable quarantine with deterministic enforcement on a dynamic workflow OR an operator-signed policy disallowing dynamic workflows in the quarantined path, plus the Q-LLM in its own ADR-0031/0037 domain with a loopback-only E2 manifest under a verify target.
- [ ] **Multi-agent authority token through a mediated IPC fabric** — `partial` — evidence: ADR-0037 Status: Proposed; only the egress-class re-aggregation bound is shipped (`verify-agent-orch` ARM CHAIN; `handleExpandTail` refuses EXPAND from gen>0). The concrete cross-domain authority-token format + budget semantics are the open design item. Done when: a concrete authority token flows through a mediated inter-agent channel with a target proving (a) attenuation across ≥2 hops for a non-egress capability and (b) a peer's output treated as untrusted input — and ADR-0037 is Accepted.
- [ ] **Collector default-deny syscall allowlist: full-coverage proof** — `shipped-live-proven` — evidence: ADR-0041 (`SystemCallFilter=@system-service bpf perf_event_open`, EPERM; collector arms E0/E2 + produces a quote under it across `verify-floor`/`verify-agent-orch`/`verify-attest`). Residual: a syscall on an unexercised GC/error path could EPERM-degrade. Done when: a literal strace across the collector's error/GC paths (or an extended fault-injection target) confirms no additional syscall is needed beyond the allowlist under all reachable conditions.
- [ ] **runsc `--platform=kvm` boundary + overhead on real /dev/kvm** — `partial` — evidence: ADR-0031; `verify-runsc-run`/`-unit` prove the portable Systrap platform under IvyBridge; the production-preferred KVM platform is probed but unusable in the harness. Done when: on `/dev/kvm` the runsc assertions pass with `--platform=kvm`, proving the production substrate boundary and acceptable overhead under a real agent loop.
- [ ] **Composed-TCB authorization invariant enforced by CI** — `shipped-live-proven` — evidence: ADR-0024 (master invariant over 13 control + 3 broker verbs + 2 chains + gates; `controlMu` wraps the multi-key reads). The kill-switch denylist is sound only because every non-agent uid-0 caller is currently TCB/untrusted-input-free — a standing human-review invariant with no CI guard. Done when: a CI lint enumerates every uid-0/root-group socket caller and fails if a new one handles untrusted input without being on a strict TCB allowlist for the kill-switch verbs.

### egress-audit-mediation

- [ ] **Structural egress: UDS group-gating + audited passthrough exception list** — `shipped-live-proven` (netns boundary) — evidence: ADR-0034 inc1 (no-route netns + single-canonical-parse proxy, SSRF/internal-IP deny; `make verify-egress-proxy`/`verify-egress-reboot`). Proxy/router UDS are mode 0666 (boundary is the netns, not socket mode); the pinned-cert/mTLS passthrough exception list is unbuilt. Done when: the UDS is group-gated to `bulkhead-egress` (target asserts a non-member DynamicUser is refused at the socket) AND an audited passthrough list exists with a target proving a pinned-cert host is allowed only via an explicit entry and logged as an uninspected channel.
- [ ] **Signed control-socket writes: off-box anchor + operator identity** — `shipped-live-proven` — evidence: ADR-0017 (`recordControl` → `control.jsonl`, domain `control`, `TestControlChainDomain`; third `verify-audit` line). Off-box anchoring of the control HEAD and an operator identity beyond uid-0 on `enforce-set` disarm are deferred. Done when: a relying party detects tail-truncation of the newest control records against an off-box anchor and an `enforce-set` disarm record carries an operator identity — both via a verify target.
- [ ] **No-rewind verdict: complete-log transport + single combined relying-party command** — `shipped-live-proven` — evidence: ADR-0026 (`verify-audit --expect-tip/--since` hash-ancestry; `verify-attest` 26.1–26.3 incl. REWOUND/FORKED). The verdict is relative to a TOFU prior observation; a complete-log transport and one combined attest+per-chain command are deferred. Done when: a documented transport reliably ships the complete current logs off-box and a single relying-party command renders the combined verdict, exercised against a withheld-log adversary.
- [ ] **Bounded-retention chains: off-box archival pull faster than prune cadence** — `shipped-live-proven` — evidence: ADR-0040 (`verifySegmentedChain` retained-head anchor, `segKeep≥1`, per-tier 8 MiB×keep-1 = 80 MiB; `make verify-audit-rotation` 19/19 across reboot). Pruned-segment tamper is caught only off-box; no archival puller ships here. Done when: an off-box archival pull (attested HEAD + segment archival) runs faster than the prune cadence, with a runbook and a monitoring check that the prior-observed HEAD is retained off-box before on-box prune.

### boot-update-attest

- [ ] **Boot-gate availability: sealed on-box high-water-mark for whole-chain-erasure detection** — `shipped-live-proven` — evidence: ADR-0030 (`verifyChainState` tolerates exactly one crash-torn tail record, fails closed otherwise; seal script refuses to mint over surviving chains; `TestVerifyChainTornTail`). Done when: on a real TPM2 a sealed monotonic high-water-mark enables on-box detection of whole-chain/tail erasure (verify target rejects erasure at boot), plus a documented off-box `--expect-tip` field check.

## How to use this

Burn down **Pilot blockers first** — they gate a controlled single-operator deployment on real hardware (bare-metal commissioning, the real-TPM2 sealed boot, the real agent-workload-on-real-model loop, the off-box chain monitor, and the minimum day-2 ops). Each item's **Done when** is the literal gate: an item is not done until its concrete, testable criterion passes — preferably as a new or extended `make verify-*` target on real hardware. Then close **GA blockers** for a hardened general release, then **Hardening** and **Nice-to-have**. This is a living document: when a gate passes, update the item's `status` (most pilot/GA items move from `build-verified-bare-metal-pending`/`partial`/`absent` toward `shipped-live-proven`) and cite the new target. Honesty over optimism — if a control has only ever run under qemu/swtpm or against a `mockchat`/slirp stub, it stays `build-verified-bare-metal-pending` or `partial` until a real-hardware / real-workload arm proves it.
